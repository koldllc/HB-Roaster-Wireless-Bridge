# 常见问题排查与技术细节指南 (Troubleshooting)

如果在连接或烘焙过程中遇到任何异常，请按照以下步骤排查。绝大多数问题都可以在 1 分钟内解决。

---

## 🛠️ 第一步：运行一键诊断工具

遇到任何网络或硬件异常时，首先在终端运行：

```bash
cd /Users/kelvinsze/Projects/hb-artisan-bridge
python3 diagnose.py
```

该工具会自动按顺序检测：
1. 本机物理网卡与当前 IP；
2. 代理软件（Loon / Surge / Clash）接管情况；
3. 向常用 IP（`192.168.88.88` 及 `192.168.4.1`）发送 TCP 16888 探测；
4. 物理网卡底层 UDP 广播；
5. Artisan 虚拟串口状态。

## ❓ 常见问题排查清单

### 1. 启动时提示「没有扫到烘焙机 / 扫描超时」

#### 原因 A：烘焙机机械电源未开启或进入深度休眠
- **表现**：执行 `diagnose.py` 提示 `超时未响应`，ARP 显示 `(incomplete) Host is down`。
- **排查**：
  1. 检查机身背部/侧面的机械电源总开关是否处于 ON。
  2. 观察机身触摸屏或数码管：烘焙机通电后，屏幕上的 Wi-Fi 标志会在数秒内常亮。
  3. 烘焙机若完成下豆且风扇停止一段时间后，可能会进入自动待机，请轻按机身按键唤醒。

#### 原因 B：Mac 电脑上运行了代理/科学上网工具（如 Loon、Clash、Surge）
- **原理**：代理工具的 Enhanced Mode（增强模式/TUN 网卡，如 `utun4`）会修改系统的全局路由表，导致系统把局域网广播地址 `255.255.255.255` 错当成外网流量发送给了虚拟网卡，而不会走 Wi-Fi 芯片（`en0`）。
- **优化对策**：
  - 中间件已升级采用 macOS 底层的 `IP_BOUND_IF` 选项，强行将 UDP 套接字绑定到物理网卡 `en0`。
  - **最稳妥的解决方案**：直接指定 IP 启动，完全不依赖广播：
    ```bash
    python3 main.py --ip 192.168.88.88
    ```
  - 或者在烘焙期间，将 Loon / Clash 暂时设置为「直连（Direct）」模式。

#### 原因 C：烘焙机掉出局域网，退回了热点（AP）模式
- **表现**：家里路由器重启或 Wi-Fi 信号不稳，烘焙机无法连接路由器。
- **排查**：
  1. 打开 Mac 或手机的 Wi-Fi 列表，看是否出现了一个名为 `ESP-HB` 的热点。
  2. 如果出现，说明烘焙机正在发射热点（默认密码 `123456789`）。
  3. Mac 可以直接连接该 `ESP-HB` 热点，然后指定热点 IP 运行：
     ```bash
     python3 main.py --ip 192.168.4.1
     ```

### 2. Artisan 点击 ON 报错：「Serial Exception: Unable to open serial port」

- **原因**：Artisan 尝试打开 `/tmp/hb_roaster` 失败。
- **解决步骤**：
  1. 检查中间件是否已经在运行：Artisan 需要连接由中间件创建的虚拟串口。请确保终端中 `python3 main.py` 已经启动，或者 `./service.sh status` 显示服务正常。
  2. 检查 Artisan 中的输入路径：确认没有多打空格或错打字符，必须是：
     ```text
     /tmp/hb_roaster
     ```
  3. 检查文件权限：在终端中输入 `ls -la /tmp/hb_roaster`，正常情况下应显示指向类似 `/dev/ttys00X` 的软链接。

---

### 3. 温度读数有时卡住，或者短暂显示 -1

- **原理**：Wi-Fi 属于无线电通信，偶尔会受到微波炉、电磁炉或物理阻隔干扰产生丢包。
- **中间件保护机制**：
  - 中间件内部内置了 **6 秒看门狗重连定时器**：如果连续 6 秒未收到烘焙机的数据包，会自动优雅断开并重新向烘焙机发起 TCP 握手。
  - Artisan 端由于连接的是本地虚拟串口，不会因为网络偶发丢包而闪退或崩溃。
- **建议**：烘焙时尽量避免机器与 Wi-Fi 路由器相隔多堵水泥墙。

## 🔬 HB 烘焙机逆向工程协议速查表

如果你对底层技术实现感兴趣，或者需要自行扩展功能，以下是该机型的底层通信规范：

### 1. 网络端口
- **UDP 自动发现端口**：`17888`
  - 广播内容：`whereareyou\r\n` (UTF-8)
  - 烘焙机响应：返回前 8 个字符为其 MAC 地址识别码（如 `603E4323`）。
- **TCP 遥测/控制端口**：`16888`
  - 长连接，双向二进制数据帧。

### 2. 二进制帧结构 (Frame Wire Format)
```text
Offset | 长度 | 含义
-------+------+-----------------------------------------------------------------
  0    |  1   | 起始引导码: 0x68
  1    |  1   | 控制码: 0x00 (读指令), 0x01 (写指令), 回复帧自动加 0x80
  2    |  1   | 序列号: 0~255 自增
  3~4  |  2   | 大端内容长度: (载荷字节数 + 1)
  5    |  1   | 数据类型 DataType (见下表)
  6..N | 载荷 | 数据 Payload
 6+len |  1   | 校验和: 从第 0 字节累加至载荷结束取低 8 位 (sum & 0xFF)
 7+len |  1   | 帧尾标识: 0x16
 8+len |  2   | 发送端附加换行: 0x0D 0x0A (\r\n)
```

### 3. 数据类型 (DataType)
- `0x02`：**实时四路温度**。读取指令 payload 为空；烘焙机回复 8 字节 Payload（4 个大端 UInt16，除以 10 即为摄氏度）：
  - `bytes[0..1]`：出风温 (Exhaust / MET)
  - `bytes[2..3]`：进风温 (Inlet / IT)
  - `bytes[4..5]`：豆温 (Bean Temperature / BT)
  - `bytes[6..7]`：环境鼓风温 (Environment Temperature / ET)
- `0x00`：**电加热开关**（1 字节：`255` 开，`0` 关）。
- `0x01`：**冷却开关**（1 字节：`stir * 2 + fan`，搅拌为高位，排风为低位）。
- `0x06`：**整机主电源**（1 字节：`255` 开，`0` 关）。
- `0x10`：**计时器开关**（1 字节：写 `2` 复位，`0` 开始运行，`1` 停止）。
- `0x11`：**计时器数值**（大端 UInt16，只读秒数）。
